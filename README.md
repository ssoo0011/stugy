# stuGy

모바일 중심의 스터디 그룹 탐색 서비스입니다. Spring Boot가 API와 React 프로덕션 빌드를 함께 제공합니다.

## 실행

백엔드와 빌드된 프론트엔드를 함께 실행합니다.

```powershell
.\gradlew bootRun
```

React 화면을 수정하면서 개발할 때는 터미널을 하나 더 열어 Vite를 실행합니다. Vite는 `/api` 요청을 Spring Boot로 전달합니다.
 
```powershell
cd frontend
npm install
npm run dev
```

## 빌드

```powershell
.\gradlew build
```

Gradle 빌드는 Node.js와 npm 패키지를 준비하고 React 결과물을 Spring Boot jar에 포함합니다.

# 스터디그룹 찾기 웹사이트 기획서

## 1. 프로젝트 개요

### 프로젝트명
스터디그룹 찾기 웹사이트

### 목표
사용자가 원하는 스터디그룹을 쉽게 찾고, 직접 스터디를 모집하거나 참여 신청할 수 있는 웹사이트를 만든다.

핵심 목적은 다음과 같다.

- 원하는 분야의 스터디를 빠르게 검색한다.
- 온라인/오프라인, 지역, 분야, 난이도 기준으로 스터디를 찾는다.
- 사용자가 직접 스터디 모집글을 작성한다.
- 참여자는 스터디에 신청하고, 스터디장은 신청자를 승인하거나 거절한다.
- 사용자는 자신이 만든 스터디와 신청한 스터디를 관리한다.

---

## 2. 핵심 사용자

### 일반 사용자
- 스터디를 찾는 사람
- 스터디에 참여 신청하는 사람
- 관심 있는 스터디를 저장하고 싶은 사람

### 스터디장
- 직접 스터디를 만들고 모집하는 사람
- 신청자를 확인하고 승인/거절하는 사람
- 스터디 멤버를 관리하는 사람

### 관리자
- 회원, 스터디 글, 신고 내역 등을 관리하는 사람

## 3. MVP 핵심 기능

처음부터 모든 기능을 만들기보다, 아래 기능을 1차 목표로 개발한다.

| 기능 | 설명                                                         |
|---|------------------------------------------------------------|
| 회원가입| 아이디, 이메일, 비밀번호, 닉네임, 지역(대한민국 기준), 생년월일, 휴대폰번호, 프로필이미지, 소개글 |
| 로그인 | 기본 로그인                                                     |
| 프로필 관리 | 닉네임, 관심 분야, 지역, 온라인/오프라인 가능 여부 관리                          |
| 스터디 목록 조회 | 등록된 스터디를 카드 형태로 조회                                         |
| 스터디 검색 | 키워드로 스터디 검색                                                |
| 스터디 필터 | 분야, 지역, 진행 방식, 모집 상태 기준 필터링                                |
| 스터디 상세 조회 | 스터디 소개, 일정, 모집 인원, 참여 조건 확인                                |
| 스터디 생성 | 사용자가 직접 스터디 모집글 작성                                         |
| 스터디 신청 | 원하는 스터디에 참여 신청                                             |
| 신청 승인 / 거절 | 스터디장이 신청자를 승인 또는 거절                                        |
| 내 스터디 관리 | 내가 만든 스터디, 신청한 스터디 확인                                      |

## 4. 스터디 생성 항목

스터디 모집글을 작성할 때 필요한 항목은 다음과 같다.

| 항목 | 예시 |
|---|---|
| 제목 | 대구 Spring Boot 백엔드 스터디 모집 |
| 카테고리 | 개발, 영어, 자격증, 취업, 독서, 운동 |
| 진행 방식 | 온라인 / 오프라인 / 혼합 |
| 지역 | 대구, 서울, 부산 등 |
| 장소 | 동성로 카페, 디스코드, Zoom |
| 모집 인원 | 4명 |
| 현재 인원 | 2명 |
| 모집 상태 | 모집중 / 마감 |
| 난이도 | 입문 / 초급 / 중급 / 고급 |
| 요일 | 월 / 수 / 금 |
| 시간 | 오후 8시 |
| 기간 | 4주, 3개월, 상시 |
| 목표 | 토이프로젝트 완성, 자격증 합격 |
| 참여 조건 | 노쇼 금지, 주 2회 참석 가능자 |
| 소개글 | 자유 입력 |
| 오픈채팅 / 디스코드 링크 | 승인된 멤버에게만 공개 가능 |

## 6. 있으면 좋은 2차 기능

MVP 개발 이후 추가하면 좋은 기능이다.

| 기능 | 설명 |
|---|---|
| 찜하기 | 관심 있는 스터디 저장 |
| 댓글 / 문의 | 신청 전 질문 가능 |
| 알림 | 신청 승인, 댓글, 모집 마감 알림 |
| 신고 기능 | 이상한 모집글 또는 사용자 신고 |
| 후기 / 평점 | 스터디 종료 후 후기 작성 |
| 출석 체크 | 실제 참여율 관리 |
| 공지사항 | 스터디장이 공지 작성 |
| 자료 공유 | 링크, 파일, 노션 주소 공유 |
| 일정 관리 | 다음 모임 날짜 등록 |
| 채팅 | 내부 채팅방 |
| 태그 | #Spring, #토익, #정보처리기사 |

> 채팅 기능은 처음부터 만들지 않는 것을 추천한다.  
> 실시간 처리, 읽음 처리, 차단, 신고, 알림까지 필요해져서 난이도가 크게 올라간다.  
> 처음에는 오픈채팅 또는 디스코드 링크를 등록하는 방식으로 대체하는 것이 좋다.

## 11. 차별화 기능 아이디어

스터디 웹사이트는 흔할 수 있기 때문에, 아래 기능을 넣으면 차별화에 도움이 된다.

| 기능 | 설명 |
|---|---|
| 스터디 성향 태그 | 빡센형, 느슨한형, 출석중요, 친목없음 |
| 목표 기반 매칭 | 정보처리기사 실기 합격, 토이프로젝트 완성 등 목표 중심 매칭 |
| 노쇼 방지 체크 | 신청 시 간단한 자기소개 또는 참여 가능 시간 입력 |
| 진행 강도 표시 | 주 1회, 주 3회, 매일 등 |
| 초보 환영 여부 | 입문자 참여 가능 여부 표시 |
| 포트폴리오형 스터디 | 결과물 링크 등록 |
| 스터디 완료 인증 | 완료한 스터디 이력 표시 |

### 스터디 분위기 예시

```text
분위기: 조용히 공부 / 빡세게 인증 / 친목 가능 / 질문 활발
강도: 낮음 / 보통 / 높음
초보 가능: 가능 / 불가능
```

## 13. MVP 결론

처음 만들 버전은 아래 기능에 집중한다.

```text
회원가입 / 로그인
프로필 관리
스터디 목록 조회
스터디 검색 / 필터
스터디 상세 조회
스터디 생성
스터디 신청
신청 승인 / 거절
마이페이지
```

2차 개발에서는 아래 기능을 추가한다.

```text
찜하기
댓글 / 문의
알림
후기
신고
관리자 페이지
```

처음부터 채팅, 실시간 알림, 추천 알고리즘까지 넣기보다는, 먼저 스터디 모집과 신청 흐름을 완성하는 것이 좋다.
